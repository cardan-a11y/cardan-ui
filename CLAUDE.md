# Cardan UI

Accessible Vue 3 component library for Nuxt 4 in TypeScript, distributed as a [Nuxt Layer](https://nuxt.com/docs/getting-started/layers). cardan-academy-nuxt (Cardan Academy), cardan-auditor-nuxt, cardan-cms-nuxt and cardan-support-nuxt extend it: `github:cardan-a11y/cardan-ui` (`main`, untagged) in production and `../cardan-ui` in development. A merge here reaches all of them at their next build.

The shared Cardan guidelines (the review before every commit, CSS, code quality, WCAG 2.2) come from the `cardan` Claude Code plugin, which adds them to every session in a Cardan repository. This repository is the plugin's home: [plugins/cardan](plugins/cardan/) holds the guidelines skill, the `cardan:cardan-reviewer` agent (and `cardan:plugin-reviewer` for a change to the plugin, CLAUDE.md or REVIEW.md alone), the review hook, the `release`, `pr-body` and `i18n-pair` skills, a Playwright MCP server, Nuxt's documentation MCP server and the cross-browser check of the review round (`scripts/cross-browser.mjs`), and [.claude-plugin/marketplace.json](.claude-plugin/marketplace.json) lists it as the `cardan-ui` marketplace, next to [plugins/cardan-browsers](plugins/cardan-browsers/): Firefox and WebKit MCP servers, off by default, switched on with `/plugin` to look into a difference the cross-browser check found. The projects enable it in their `.claude/settings.json`, where the marketplace auto-updates: a merge into `main` reaches a session within minutes of its start and applies from the next launch or `/reload-plugins`. A machine that added the marketplace from a local checkout (`claude plugin list` shows "Read from" this folder) runs the checkout as it is, branch and uncommitted changes included, in every project. How to try a change to the plugin is in [plugins/CLAUDE.md](plugins/CLAUDE.md).

## Working here

- **Branches**: `main` is what the projects build from. Work starts on the release branch of the next patch version, `release/<version>`, cut from `main`: fixes are bundled there until `/cardan:release` makes them a version and opens the pull request, and after the merge the next release branch is cut. A change that must reach the projects before the rest gets its own branch and pull request. Releases are not tagged.
- **Checks**: `pnpm run lint`, `pnpm run typecheck` (vue-tsc over the playground's generated project; it passes on `main`, so a type error is a signal), `pnpm test` and `pnpm test:browser` (see Tests). CI runs all four on every pull request and on `main`, the browser suite on the playground's production build. There is no review in GitHub Actions: the local review before every commit is the review.
- **Done means**: the checks pass; the change was tried in the playground with the keyboard, at 320px and at desktop width, in both locales and both color modes (the plugin's Playwright MCP server does this in Chrome from the session; the review round runs its cross-browser check in Chrome, Firefox and WebKit); a changed component has a test that pins the change, in `test/browser/` when only a browser shows it; before a release `pnpm test:projects` passed; the local review ran and its tally is in the PR description (`cardan:pr-body`).
- **Release**: `/cardan:release`: the version in `package.json`, an entry in [.playground/pages/changelog.vue](.playground/pages/changelog.vue), a section in [MIGRATION.md](MIGRATION.md) with what projects must do (one line when they need to do nothing), then the PR.
- **The review gate** only sees the commands Claude runs: a push from your own terminal is not gated.
- **Machine-specific**: the projects are checked out next to this one in `~/Development` and extend `../cardan-ui`; the playground runs on port 3003 (`pnpm dev`). A cloud session has only this repository and the playground.
- **Local servers** (check `lsof -iTCP -sTCP:LISTEN` before starting one): the auditor runs on 3000, the academy on 3005; both APIs use port 8000, so one at a time. How to start each, its sign-in and the auditor's tests against this checkout are in `../cardan-auditor-nuxt/CLAUDE.md` and `../cardan-academy-nuxt/CLAUDE.md`.

## Tests

- **What runs where**: `pnpm test` is vitest in happy-dom: names, roles, states, ARIA references, key handlers, events, axe without layout. It cannot prove focus (anything takes `focus()`), Tab order, a native dialog's or popover's behaviour, hidden or `inert` content, or contrast. `pnpm test:browser` (Playwright, Chromium, the built playground, test/browser/) does: focus and Tab, Dialog and Popover, hidden content, the token contrast and every playground page in both modes with axe. `pnpm test:projects` runs each sibling project's `test:layer` against this checkout and, once it passes, its `test:browser`, one project at a time, before a release; `pnpm test:projects --skip-browser` runs only the `test:layer` suites.
- **Helpers**, which the projects import from the sibling checkout for their own wrappers and pages: [test/a11y.ts](test/a11y.ts) (`checkA11y`, `accessibleName`, `roleOf`, `description`, `expectFocused`), [test/dom.ts](test/dom.ts) (`press`, `addToPage`, `toggle`, `afterRouteFocus`), [test/form.ts](test/form.ts) (`mountInForm`), [test/fetch.ts](test/fetch.ts) (`fetchError`), [test/tokens.ts](test/tokens.ts) (the token contract with a `main.css`) and [test/browser/helpers.ts](test/browser/helpers.ts) (focus walks, Chromium's accessibility node, axe, contrast).
- **Principle**: a test pins what a user or assistive technology can observe, following the APG pattern or the deviation the component's docblock documents (SpinButton's test is the model). No class or visual assertions, except contrast. A defect a test exposes is fixed, or left as a named `it.todo` (`test.fixme` in the browser) with its cause: never tested around.
- **The projects as scenarios**: each project's `main.css` goes through the token and contrast checks, real failed-request bodies of their backends are fixtures in `test/fixtures/api-errors/`, and the auth tests run in the Academy's and the Auditor's configuration.

## Components

One file per component in [app/components/](app/components/), auto-imported by file name. The playground at `http://localhost:3003` ([.playground/pages/](.playground/pages/)) shows nearly all of them with live examples of most props. What a listing cannot show:

- **MarkdownPreview** ([app/components/Markdown/](app/components/Markdown/), markdown-it; highlight.js with the grammars in `highlight.ts` loads after mount, only when a text has a code block) is safe by default: raw HTML shows as text and `{…}` sets only `lang`, `dir` and `class`; `trusted` allows both, for text the team wrote. `inline` renders a title or label in a `<span>`, `heading-offset` moves headings down. A bare YouTube or Vimeo link in a paragraph of its own renders as VideoPlayer, also without `trusted`; a link with its own text, or one in an `inline` text or with `videos-as-links` (a table cell), stays a link. A link opens in a new window only when it goes to another origin. **MarkdownEditor** wraps md-editor-v3.
- **VideoPlayer** plays YouTube and Vimeo videos: a thumbnail and a play button first, the player after a click. `parseVideoUrl()` in [app/utils/video.ts](app/utils/video.ts) decides which URLs it plays, for MarkdownPreview too. It needs `@nuxt/image` in the project, which the layer does not register, with the thumbnail hosts in its `image.domains`: `['i.ytimg.com', 'i.vimeocdn.com']`.
- **CardanLogo**: full, symbol and tile forms, color variants and product lockups (`product="academy"` shows "| Academy"; the product name is always Hanken Grotesk, in Body or white, never purple). 20px high by default; in a flex row a lockup takes the room it gets, from 144px (`narrow-width`) up to its height. The favicon is the light round tile with the symbol at 72%.
- **Accordion** is the APG accordion: a button in a heading (`h-tag`) that opens a panel, inert while closed and a `region` landmark only with the `region` prop; the panel's overflow follows its state, so nothing in it is clipped once open. **AccordionDetails** is the native `<details>`.
- **FormField** is the frame the field components share: the label with its required chip, the control in its slot, the error text and the instruction, with the styles they share. A new field component renders through it and points its control at `instruction-<id>` with `aria-describedby`, and at `error-<id>` only while the error shows: after a failed submit of its Form (`formShowInvalidKey`, which Form provides) or with `show-invalid`. `error-message` is the text for a constraint the browser checks (Input adds to its `pattern` what the Laravel APIs refuse: a required value of only spaces and an e-mail domain without a dot; Textarea, which has no `pattern`, leaves only spaces to the API); `custom-error` (on every field but FileInput, RangeInput and Switch) shows an error the browser cannot find, such as one from the server, and describes the field by it until its value changes, without holding the form back. An attribute on Input, Textarea or Select goes to the control, on MultiSelect or DatePicker it reaches the library's component; `class` and `style` go to the wrapper.
- **SpinButton** is the alternative to `<Input type="number">` for a whole number of zero or more, such as a quantity: the APG spinbutton, with where it leaves the pattern and why in its docblock. `v-model` is a number, `undefined` while the field is empty, and follows every keystroke; `change` says the number is final. `test/components/SpinButton.test.ts` follows the rows of the APG pattern.
- **Dialog** is a native `<dialog>`, opened and closed through its exposed `openDialog()` and `closeDialog()`, and `--dialog-max-width` on its class sets its width (800px at the side by default; a centered dialog without it is as wide as its content); **Tooltip** and **Popover** use the native Popover API and CSS anchor positioning (README has the browser baseline); Popover is a disclosure (a list of links or buttons, no menu roles): when it opens focus moves to its first item, Tab past the last leaves and closes it, Escape returns focus to the trigger; **Callout** has `solid` (default) and `outline` variants; **FocusLoop** keeps Tab in a container and, when modal, makes the rest of the page `inert` while it is open (the component that can break a whole page: its tests in `test/components/FocusLoop.test.ts` cover every way it opens and closes); **FileInput** compresses images with compressorjs; with `mode="document"` it checks a file against the extensions in `accept` and hands it to the parent to upload (`select`), uncompressed, and `shape="circle"` is the avatar upload.
- **MultiSelect** wraps @vueform/multiselect and **DatePicker** wraps Vue DatePicker, both external libraries with known accessibility flaws; MultiSelect is on the roadmap to be replaced by our own. Fix them through the library's configuration (props, events, slots) or, where it offers none, inside the wrapper itself, like DatePicker's attributes on the library's input and MultiSelect's dropdown placement. Never work around them in another component (Popover, FocusLoop, a project); a flaw the wrapper cannot fix is reported and left.
- **ErrorMessage** is the error box of a form or a page, in every project and the auth layer. `extractApiError()` ([app/utils/api.ts](app/utils/api.ts)) reads what a failed request threw, in either shape the Laravel APIs answer in (Laravel's `{ message, errors: { field: [...] } }`, the JSON:API envelope of the Academy's `/api/v1`), with the `Content-Language` (English without one); `useErrorMessage()` keeps it as `errorData` for the box. Without a usable answer the box says, in the page's language, that the browser was offline (read from `navigator.onLine` as the request fails, so the text does not change when the connection comes back) or that something went wrong (an HTML error page, a server that did not answer). Its `text` prop is page text, shown before the API's messages; it takes no outer margin.
- **The error page** ([app/error.vue](app/error.vue)) is every project's that has none of its own: **ErrorPageContent** in the route's layout, so the layout, not `app.vue`, holds the frame (AppShell, the header, `<main>`), and CSS and `titleTemplate` come from `nuxt.config.ts`. A heading and text per status, also the title, and one link on: back to the page before (Vue Router's `history.state.back`, or a same-origin referrer), else home. A page's own text goes in `data: { text }`; `statusText` and the stack show in development only. It reads nothing but the error. A page that answers 404 itself renders ErrorPageContent too.
- **The app shell**: **AppShell**, **AppHeader**, **AppSidebar** and **SidebarLayout** hold the layout rules the apps share (what sticks where, what scrolls on its own, where focus goes after a navigation) and leave the look to each app's CSS variables, which their docblocks list. `/layout` in the playground shows them, and the playground uses all four. `useRouteFocus()` also focuses when the shell mounts after the app has started (around the error page), and leaves focus that the new page moves itself (the second factor's code field, AuthPage's frame); everything sticky shares AppHeader's condition, 360px wide and 480px high. A page's spacing above and below belongs inside the columns of a SidebarLayout, never on a wrapper: a sticky panel cannot enter its container's padding and is cut off above it. A project's own component with one of these names shadows the layer's.
- **Composables** in [app/composables/](app/composables/): `useToast()` queues the toasts that **ToastManager** shows and hides one by its id (not for a message from an open modal Dialog or MobileMenu: the toast is under its backdrop, out of reach and unannounced, so that message shows in the dialog, with ErrorMessage); `useCookiesDialog()` holds the cookie consent that **CookiesDialog** collects and applies (after an Accept it loads GTM with `runtimeConfig.public.gtmId`, and nothing from Google without one), and the open flag the dialog follows (`openCookiesDialog()`), so any component reads it without repeating that work; `useScreenSize()` exposes the breakpoints and the pointer type as refs; `useDate()` formats relative dates in the current locale. `useResultsFocus()` brings a list of results to the reader after it changes in place (pagination, filters), and `useHashFocus()` focuses the element the address's hash names once a page's content has rendered.
- `<html lang>` and `dir` follow the i18n locale, set by the layer's plugin [app/plugins/html-lang.ts](app/plugins/html-lang.ts); a project sets neither.
- Shared types are `declare global` in [app/types/index.ts](app/types/index.ts).

## Cardan Auth UI layer

The [auth/](auth/) directory is a separate, opt-in Nuxt layer (`@cardan/auth-ui`) with the sign-in and MFA forms for Nuxt SPAs backed by Laravel Fortify, demoed in the playground at `/auth` with mock endpoints in `.playground/server/routes`. Its conventions are in [auth/CLAUDE.md](auth/CLAUDE.md), its documentation in [auth/README.md](auth/README.md).

## CSS variables

All global CSS variables for color, spacing, typography, etc. are declared in [main.css](app/assets/main.css). The layer does not load this file: it is the Cardan template that each consuming project copies into its own `main.css` (a stylesheet shipped by the layer would add a render-blocking request). The playground imports it from [playground.css](.playground/assets/playground.css).

- The `--cardan-*` primitives hold the brand palette; components never use them, only the semantic `--color-*` tokens do.
- Custom properties that a component sets for itself, such as from a `fontSize` or `iconSize` prop, are prefixed with the component name (`--button-icon-size`, not `--icon-size`), so they don't leak into nested components.
- A component preferably reads a shared token bare, `var(--color-text)`, so a missing token shows up instead of being papered over, and never chains `var(--new-token, var(--old-token))` to paper over a rename. A default in `var()` is fine where it makes sense, such as for a component's own property that a prop or a parent may set, `var(--button-radius, var(--radius-md))`. When a component needs a new token, add it to `main.css` and to the release's section in [MIGRATION.md](MIGRATION.md), with a value that keeps the current look of existing projects.
- Every text and graphic token pair must meet WCAG 2.2 AA contrast (4.5:1 for text, 3:1 for graphics) in light and dark mode. Never fix a contrast failure by inventing a new color; use a brand token.
- Text and icons on tinted (`-bg`) surfaces use the matching `--color-*-text` token; every `-text` token must reach 4.5:1 on its `-bg` surface.

## Icons

Components take an `icon` prop, powered by [@nuxt/icon](https://nuxt.com/modules/icon) and Iconify. Use [Material Symbols](https://icones.js.org/collection/material-symbols): `material-symbols:<name>-outline-rounded` first, `-rounded` when the design wants a filled icon, the plain name when neither variant exists. Icons are decorative (hidden from screen readers) unless the component has no text label, so give an icon-only control an `aria-label`. An icon a component shows on first paint goes into `bundledIcons` in [app/utils/icons.ts](app/utils/icons.ts), which the layer's `nuxt.config.ts` puts in the client bundle of every project, so the page does not shift when it loads. A listed icon whose collection a project does not install fails that project's production build, so it comes from Material Symbols or `svg-spinners`, which every project installs.

The plugin's `nuxt` MCP server is the Nuxt team's documentation (`https://nuxt.com/mcp`); the playground has no MCP endpoint of its own.
