# Cardan UI

Accessible Vue 3 component library for Nuxt 4 in TypeScript, distributed as a [Nuxt Layer](https://nuxt.com/docs/getting-started/layers). cardan-academy-nuxt (Cardan Academy), cardan-auditor-nuxt, cardan-cms-nuxt and cardan-support-nuxt extend it: `github:cardan-a11y/cardan-ui` (`main`, untagged) in production and `../cardan-ui` in development and tests. A merge here reaches all of them at their next build.

The shared Cardan guidelines (the review before every commit, CSS, code quality, WCAG 2.2) come from the `cardan` Claude Code plugin, which adds them to every session in a Cardan repository. This repository is the plugin's home: [plugins/cardan](plugins/cardan/) holds the guidelines skill, the `cardan:cardan-reviewer` agent (and `cardan:plugin-reviewer` for a change to the plugin, CLAUDE.md or REVIEW.md alone), the review hook, the `release`, `pr-body` and `i18n-pair` skills, a Playwright MCP server, Nuxt's documentation MCP server and the cross-browser check of the review round (`scripts/cross-browser.mjs`), and [.claude-plugin/marketplace.json](.claude-plugin/marketplace.json) lists it as the `cardan-ui` marketplace, next to [plugins/cardan-browsers](plugins/cardan-browsers/): Firefox and WebKit MCP servers, off by default, switched on with `/plugin` to look into a difference the cross-browser check found. The projects enable it in their `.claude/settings.json`, where the marketplace auto-updates: a merge into `main` reaches a session within minutes of its start and applies from the next launch or `/reload-plugins`. A machine that added the marketplace from a local checkout (`claude plugin list` shows "Read from" this folder) runs the checkout as it is, branch and uncommitted changes included, in every project. How to try a change to the plugin is in [plugins/CLAUDE.md](plugins/CLAUDE.md).

## Working here

- **Branches**: `main` is what the projects build from. Work starts on the release branch of the next patch version, `release/<version>`, cut from `main`: fixes are bundled there until `/cardan:release` makes them a version and opens the pull request, and after the merge the next release branch is cut. A change that must reach the projects before the rest gets its own branch and pull request. Releases are not tagged.
- **Checks**: `pnpm run lint`, `pnpm run typecheck` (vue-tsc over the playground's generated project; it passes on `main`, so a type error is a signal), `pnpm test` and `pnpm test:browser` (see Tests). CI runs all but `pnpm test:browser` on every pull request and on `main`, and builds the playground; the browser suite runs locally only (Actions minutes). There is no review in GitHub Actions: the local review before every commit is the review.
- **Done means**: the checks pass; the change was tried in the playground with the keyboard, at 320px and at desktop width, in both locales and both color modes (the plugin's Playwright MCP server does this in Chrome from the session; the review round runs its cross-browser check in Chrome, Firefox and WebKit); a changed component has a test that pins the change, in `test/browser/` when only a browser shows it; before a release `pnpm test:projects` passed; the local review ran and its tally and findings are in the PR description (`cardan:pr-body`).
- **Release**: `/cardan:release`: the version in `package.json`, an entry in [.playground/pages/changelog.vue](.playground/pages/changelog.vue), a section in [MIGRATION.md](MIGRATION.md) with what projects must do (one line when they need to do nothing), then the PR.
- **The review gate** only sees the commands Claude runs: a push from your own terminal is not gated.
- **Machine-specific**: the projects are checked out next to this one in `~/Development` and extend `../cardan-ui`; the playground runs on port 3003 (`pnpm dev`, on this machine only; `pnpm dev:public` makes it reachable from the network, e.g. to test on a phone). A cloud session has only this repository and the playground.
- **Local servers** (check `lsof -iTCP -sTCP:LISTEN` before starting one): the auditor runs on 3000, the academy on 3005; both APIs use port 8000, so one at a time. How to start each, its sign-in and the auditor's tests against this checkout are in `../cardan-auditor-nuxt/CLAUDE.md` and `../cardan-academy-nuxt/CLAUDE.md`.

## Tests

- **What runs where**: `pnpm test` is vitest in happy-dom: names, roles, states, ARIA references, key handlers, events, axe without layout. It cannot prove focus (anything takes `focus()`), Tab order, a native dialog's or popover's behaviour, hidden or `inert` content, or contrast. The components, composables and utils share one playground app per worker ([vitest.config.ts](vitest.config.ts)), so a test there puts back what it changed beyond what `test/setup.ts` resets (the clock, the language, mounted components); a file that mocks a module (found by its `vi.mock`, `mockNuxtImport` or `mockComponent`), and the auth layer's, run in an app of their own. `pnpm test:browser` (Playwright, Chromium, the built playground, test/browser/) does: focus and Tab, Dialog and Popover, hidden content, the token contrast and every playground page in both modes with axe. `pnpm test:projects` runs each sibling project's `test:layer` against this checkout (each checkout on its current branch, or with `--branch <name>` on the branch that waits for this release, switched back afterwards, plus waiting branches in worktrees beside it; it names the unmerged branches it skipped) and, once it passes, its `test:browser`, one project at a time, before a release; `pnpm test:projects --skip-browser` runs only the `test:layer` suites.
- **Helpers**, which the projects import from the sibling checkout for their own wrappers and pages: [test/a11y.ts](test/a11y.ts) (`expectNoViolations`, `checkA11y`, `accessibleName`, `roleOf`, `description`, `expectFocused`), [test/dom.ts](test/dom.ts) (`press`, `addToPage`, `toggle`, `afterRouteFocus`, `clickBackdrop`, `addRoutes`), [test/form.ts](test/form.ts) (`mountInForm`), [test/fetch.ts](test/fetch.ts) (`fetchError`), [test/identity.ts](test/identity.ts) (`loadIdentity`, for a test of the start-up), [test/tokens.ts](test/tokens.ts) (the token contract with a `main.css`) and [test/browser/helpers.ts](test/browser/helpers.ts) (focus walks, Chromium's accessibility node, axe, contrast).
- **The harness**, the tooling around the tests, which the layer uses itself and a project may adopt in place of its own copy: [test/config/](test/config/) (`cardanVitestConfig`, `cardanVitestProjects`, `serve`, `cardanPlaywrightConfig`, imported by a relative path since config files load before any alias; they import only Node built-ins and return plain objects, so every package is the project's), [test/tripwires.ts](test/tripwires.ts) (the runner of a project's `test/tripwires.test.ts`, for a last resort only; the layer has no entry), the API fakes that fail a test on a request no route answers ([test/api.ts](test/api.ts) for vitest, whose [test/api-setup.ts](test/api-setup.ts) mocks the Sanctum client for every test once listed; [test/browser/api.ts](test/browser/api.ts) for Playwright, `withApi()`), the console guard that fails a test on a console error or warning (a Vue warning among them) unless the test names it ([test/console.ts](test/console.ts), `expectConsole()`, listed by `failOnConsole: true`; [test/browser/console.ts](test/browser/console.ts), `withConsole()`, which every layer spec gets from `test/browser/test.ts`: console errors, hydration warnings and uncaught errors, named with `pageErrors.expect()`), the guard that aborts a browser request to another origin and fails the test unless it answers it ([test/browser/network.ts](test/browser/network.ts), `withOtherOrigins()`, `otherOrigins.answer()`, also through `test/browser/test.ts`, with an `allow` option for a project's own backend on another origin; the server's own requests are not seen) and [.github/workflows/project.yml](.github/workflows/project.yml), the projects' CI job. [test/harness.test.ts](test/harness.test.ts) pins them.
- **Principle**: a test pins what a user or assistive technology can observe, following the APG pattern or the deviation the component's docblock documents (SpinButton's test is the model), and what a third party can observe: nothing leaves the page for a third party before the user asked for it, and a test fails when it does. No class or visual assertions, except contrast. A defect a test exposes is fixed, or left as a named `it.todo` (`test.fixme` in the browser) with its cause: never tested around. A workaround uses a dependency's public API; only one that has to read its internals or rely on behaviour it does not document, because no public way exists, has a tripwire entry, which fails once that dependency moves on, or a test on the real dependency that its comment names (`withAxe()` in `test/a11y.ts`).
- **The projects as scenarios**: [test/projects.json](test/projects.json) is the list `pnpm test:projects` reads (a new project also goes in this file's first paragraph, REVIEW.md, `plugins/cardan/agents/plugin-reviewer.md` and the release skill's description); each project checks its own `main.css` with the token and contrast helpers in its own suite (the layer checks only the template), real failed-request bodies of their backends are fixtures in `test/fixtures/api-errors/`, and the auth tests run in the Academy's and the Auditor's configuration (`test/setup.ts` answers the identity request at start-up as a guest; the apps in `test/fixtures/auth-app*` pin the layer's merged config and middleware order).

## Components

One file per component in [app/components/](app/components/), auto-imported by file name. The playground at `http://localhost:3003` ([.playground/pages/](.playground/pages/)) shows nearly all of them with live examples of most props. What a listing cannot show:

- **MarkdownPreview** ([app/components/Markdown/](app/components/Markdown/), markdown-it; highlight.js with the grammars in `highlight.ts` loads after mount, only when a text has a code block) is safe by default: raw HTML shows as text, `{…}` sets only `lang`, `dir` and `class`, and an image loads only from the page's origin or a first-party host in the app config's `cardan.markdownImageHosts`, else it is a link; `trusted` allows all three, for text the team wrote. `inline` renders a title or label in a `<span>`, `heading-offset` moves headings down. A bare YouTube or Vimeo link in a paragraph of its own renders as VideoPlayer, also without `trusted`; a link with its own text, or one in an `inline` text or with `videos-as-links` (a table cell), stays a link. A link opens in a new window only when it goes to another origin. **MarkdownEditor** wraps md-editor-v3.
- **VideoPlayer** plays YouTube and Vimeo videos: a thumbnail and a play button first, the player after a click. `parseVideoUrl()` in [app/utils/video.ts](app/utils/video.ts) decides which URLs it plays, for MarkdownPreview too; any other web address is a plain link, without a request. Title and size come from the layer's route `/_cardan/video/<provider>/<id>` ([server/routes/_cardan/](server/routes/_cardan/), cached a day, 3 s to answer), never from the browser to the provider; the `title` prop skips it. It needs `@nuxt/image` in the project, which the layer does not register; the layer lists the thumbnail hosts in `image.domains` itself (README, "What the layer configures"). **YouTube** (Nuxt Scripts' player) is deprecated for VideoPlayer and goes in the next minor.
- **CardanLogo**: full, symbol and tile forms, color variants and product lockups (`product="academy"` shows "| Academy"; the product name is always Hanken Grotesk, in Body or white, never purple). 20px high by default; in a flex row a lockup takes the room it gets, from 144px (`narrow-width`) up to its height. The favicon is the light round tile with the symbol at 72%.
- **Accordion** is the APG accordion: a button in a heading (`h-tag`) that opens a panel, inert while closed and a `region` landmark only with the `region` prop; the panel's overflow follows its state, so nothing in it is clipped once open. **AccordionDetails** is the native `<details>`.
- **FormField** is the frame the field components share: the label with its required chip, the control in its slot, the error text and the instruction, with the styles they share. A new field component renders through it, takes a value an extension filled in without an input event through `useAutofillSync()` (on `change` and before its Form checks a submit), and points its control at `instruction-<id>` with `aria-describedby`, and at `error-<id>` only while the error shows: after a failed submit of its Form (`formShowInvalidKey`, which Form provides; `resetValidity()` or a reset hides it again) or with `show-invalid`, never while disabled or read-only, which the browser does not check; `useCustomError()` and `useControlAttrs()` hold that error state and the attributes for the control. `error-message` is the text for a constraint the browser checks (Input adds to its `pattern` what the Laravel APIs refuse: a required value of only spaces and an e-mail domain without a dot; Textarea, which has no `pattern`, leaves only spaces to the API); `custom-error` (on every field but FileInput, RangeInput and Switch) shows an error the browser cannot find, such as one from the server, and describes the field by it until its value changes, without holding the form back. An attribute on Input, Textarea or Select goes to the control, on MultiSelect or DatePicker it reaches the library's component (DatePicker's `placeholder` and `aria-describedby` go to its own input in the library's `dp-input` slot); `class` and `style` go to the wrapper.
- **SpinButton** is the alternative to `<Input type="number">` for a whole number of zero or more, such as a quantity: the APG spinbutton, with where it leaves the pattern and why in its docblock. `v-model` is a number, `undefined` while the field is empty, and follows every keystroke; `change` says the number is final. `test/components/SpinButton.test.ts` follows the rows of the APG pattern.
- **ComboBox** is the searchable single select, our own, that replaces MultiSelect: the APG combobox with a listbox popup, with where it leaves the pattern and why in its docblock (the value is always an option, never the typed text; `aria-selected` marks the value, `aria-activedescendant` the highlight; typing highlights nothing). `v-model` is the option's value (`null` after a clear) and `v-model:selected` the option itself, so a field shows its label without its list; `options` is an array or a function, asked when the field is first touched and again only after a failure (`error` gives its cause) or an empty answer, a new `options-key` or `refreshOptions()`; with `server-search` the function searches (`options(query, { signal, page })`, after a pause in typing) and may answer in pages (`{ options, more }`), and a value then needs `v-model:selected`. It settles when focus leaves and before its Form checks a submit (it registers with `formSyncKey` itself, not through `useAutofillSync()`: an extension has nothing to fill in), `name` goes to a hidden input with the value, and its list is in the top layer, placed with anchor positioning; the only measurement in JavaScript is for the phone's keyboard (`visualViewport`): the list keeps out from under it, and a field it still hides is scrolled into view. No separate behaviour on a touch screen. `create-option` adds a last option that emits `create` with the typed text (not with `server-search`), and an option whose `disabled-key` field is set is `aria-disabled`: reached by the arrow keys and a search, never picked; Tab picks only an existing, enabled option. `test/components/ComboBox.test.ts` follows the rows of the APG example.
- **ComboBox `multiple`** selects several options, replacing MultiSelect's `multiple` and `tags` modes: the same field with a popup that is a non-modal `dialog` of real Checkbox components, since no pattern describes several values in one listbox combobox; focus moves into the dialog to tick and Escape returns it, with the rest in the docblock. `multiple` is read once and types the model (`generic="T, M extends boolean"`): `v-model` is an array of values (`v-model:selected` the options), `name` gives a hidden input per value, `create-option` a button that emits `create` with the typed text, a disabled option is an `aria-disabled` Checkbox that Tab still reaches, and `server-search` is ignored; a warning in development tells a mode change after mount or a value of the other mode's type. ComboBox.vue holds the template and calls `useComboBoxField()` (focus, settling, the Form sync, validity) and `useComboBoxSingle()` or `useComboBoxMultiple()` (the selection and the keyboard), next to `useComboBoxOptions()`, `useComboBoxStatus()` and `useComboBoxPopup()`.
- **Dialog** is a native `<dialog>`, opened and closed through its exposed `openDialog()` and `closeDialog()` (which resolves once the exit animation has played and the dialog has closed), and `--dialog-max-width` on its class sets its width (800px at the side by default; a centered dialog without it is as wide as its content); **Tooltip** and **Popover** use the native Popover API and CSS anchor positioning (README has the browser baseline); Popover is a disclosure (a list of links or buttons, no menu roles), as is UserMenu on the same API: when it opens focus moves to its first item, Tab past the last leaves and closes it, Escape returns focus to the trigger (its own sign-out dialog, `logout` and `openLogoutDialog()`, is deprecated for the auth layer's LogoutDialog and goes in the next major); **Callout** has `solid` (default) and `outline` variants; **FocusLoop** keeps Tab in a container and, when modal, makes the rest of the page `inert` while it is open (the component that can break a whole page: its tests in `test/components/FocusLoop.test.ts` cover every way it opens and closes); **FileInput** compresses images with compressorjs, loaded on the first image, which a project that uses it installs itself (README lists each component's packages), and puts the result in its input too: from `ready` on (also for an image it leaves as it is, or could not compress) a form post carries the final file, before that the original; in image mode, `accept` (a MIME type, `image/*` or an extension) turns down a file of another type, also one dropped or pasted; `reset()` empties the value, the input and the preview; with `mode="document"` it checks a file against the extensions in `accept` and hands it to the parent to upload (`select`), uncompressed; with `name` it also keeps the file as its value and in the input a form post reads, so `required` holds a submit back; `shape="circle"` is the avatar upload.
- **ConfirmDialog** asks before an action, such as a delete: an alertdialog on Dialog whose focus starts on Cancel (Dialog's `focus-cancel`). With `challenge` the user types a digit first, and focus starts as in any Dialog, or in that field with `autofocus`. `confirm` asks its owner to act, who closes it or shows the failure in `error`; every other way out emits `cancel`. From script, `useConfirm().confirm({ label, description, onConfirm: () => deleteAudit(audit) })` opens the one **ConfirmDialogHost** renders, which a project mounts once in its layout. The rule: the action travels with the request, as a function that closes over its item, so nothing shared holds an item or decides which handler runs; a second `confirm()` while one is open resolves `false`.
- **MultiSelect** wraps @vueform/multiselect and **DatePicker** wraps Vue DatePicker, both external libraries with known accessibility flaws; MultiSelect is deprecated for ComboBox (with `multiple` for several) and goes in the next minor, so it gets no new work. Fix them through the library's configuration (props, events, slots) or, where it offers none, inside the wrapper itself, like DatePicker's own input in the library's `dp-input` slot and MultiSelect's dropdown placement. Never work around them in another component (Popover, FocusLoop, a project); a flaw the wrapper cannot fix is reported and left.
- **ErrorMessage** is the error box of a form or a page, in every project and the auth layer. `extractApiError()` ([app/utils/api.ts](app/utils/api.ts)) reads what a failed request threw, in either shape the Laravel APIs answer in (Laravel's `{ message, errors: { field: [...] } }`, the JSON:API envelope of the Academy's `/api/v1`), with the `Content-Language` (English without one); `useErrorMessage()` keeps it as `errorData` for the box. Without a usable answer the box says, in the page's language, that the browser was offline (read from `navigator.onLine` as the request fails, so the text does not change when the connection comes back) or that something went wrong (an HTML error page, a server that did not answer). Its `text` prop is page text, shown before the API's messages; it takes no outer margin.
- **EmptyMessage** is the text of an empty list or search, with an `actions` slot for a button such as "Reset filters"; its docblock lists the variables for its look. It takes no outer margin and is not a live region: a list that changes in place tells the reader through `useResultsFocus()` or the page's own status element, and an action that removes the message moves focus itself.
- **The error page** ([app/error.vue](app/error.vue)) is every project's that has none of its own: **ErrorPageContent** in the route's layout, so the layout, not `app.vue`, holds the frame (AppShell, the header, `<main>`), and CSS and `titleTemplate` come from `nuxt.config.ts`. A heading and text per status, also the title, and one link on: back to the page before (Vue Router's `history.state.back`, or a same-origin referrer), else home. A page's own text goes in `data: { text }`; `statusText` and the stack show in development only. It reads nothing but the error. A page that answers 404 itself renders ErrorPageContent too.
- **The app shell**: **AppShell**, **AppHeader**, **AppSidebar** and **SidebarLayout** hold the layout rules the apps share (what sticks where, what scrolls on its own, where focus goes after a navigation) and leave the look to each app's CSS variables, which their docblocks list. `/layout` in the playground shows them, and the playground uses all four. `useRouteFocus()` also focuses when the shell mounts after the app has started (around the error page), and leaves focus that the new page moves itself (the second factor's code field, AuthPage's frame); everything sticky shares AppHeader's condition, 360px wide and 480px high. A page's spacing above and below belongs inside the columns of a SidebarLayout, never on a wrapper: a sticky panel cannot enter its container's padding and is cut off above it. A project's own component with one of these names shadows the layer's.
- **Composables** in [app/composables/](app/composables/): `useToast()` queues the toasts that **ToastManager** shows and hides one by its id (not for a message from an open modal Dialog or MobileMenu: the toast is under its backdrop, out of reach and unannounced, so that message shows in the dialog, with ErrorMessage); `useCookiesDialog()` holds the cookie consent that **CookiesDialog** collects and applies (after an Accept it loads GTM with `runtimeConfig.public.gtmId`, and nothing from Google without one; a project never registers GTM itself and sends its own events with `pushDataLayer()`, dropped until an Accept), and the open flag the dialog follows (`openCookiesDialog()`), so any component reads it without repeating that work; `useDialog(key)` holds a dialog's ref under a key, so one component binds it to its Dialog or MobileMenu and any other opens it with `useDialog(key).open()` (one mounted dialog per key; a project lists its keys in the global `DialogKeys` interface to make a typo a type error, and the auth layer's are `auth:*`); `useScreenSize()` exposes the breakpoints and the pointer type as refs; `useDate()` formats relative dates in the current locale; `useNumber()` formats numbers, percentages and prices in it ([app/utils/number.ts](app/utils/number.ts)). `useResultsFocus()` brings a list of results to the reader after it changes in place (pagination, filters), and `useHashFocus()` focuses the element the address's hash names once a page's content has rendered.
- `<html lang>` and `dir` follow the i18n locale, set by the layer's plugin [app/plugins/html-lang.ts](app/plugins/html-lang.ts), and its module [modules/html-lang.ts](modules/html-lang.ts) gives the shell of an `ssr: false` route the default locale's language; a project sets neither.
- Shared types are `declare global` in [app/types/index.ts](app/types/index.ts).

## Cardan Auth UI layer

The [auth/](auth/) directory is a separate, opt-in Nuxt layer (`@cardan/auth-ui`) with the sign-in and MFA forms for Nuxt SPAs backed by Laravel Fortify, and the Sanctum setup the apps share (the module and its defaults, the identity load with `$identityReady`, the language from the address and the profile), demoed in the playground at `/auth` with mock endpoints in `.playground/server/routes`; the playground turns the module's global middleware off. Its conventions are in [auth/CLAUDE.md](auth/CLAUDE.md), its documentation in [auth/README.md](auth/README.md).

## CSS variables

All global CSS variables for color, spacing, typography, etc. are declared in [main.css](app/assets/main.css). The layer does not load this file: it is the Cardan template that each consuming project copies into its own `main.css` (a stylesheet shipped by the layer would add a render-blocking request). The playground imports it from [playground.css](.playground/assets/playground.css).

- The `--cardan-*` primitives hold the brand palette; components never use them, only the semantic `--color-*` tokens do.
- Custom properties that a component sets for itself, such as from a `fontSize` or `iconSize` prop, are prefixed with the component name (`--button-icon-size`, not `--icon-size`), so they don't leak into nested components.
- A component preferably reads a shared token bare, `var(--color-text)`, so a missing token shows up instead of being papered over, and never chains `var(--new-token, var(--old-token))` to paper over a rename. A default in `var()` is fine where it makes sense, such as for a component's own property that a prop or a parent may set, `var(--button-radius, var(--radius-md))`. When a component needs a new token, add it to `main.css` and to the release's section in [MIGRATION.md](MIGRATION.md), with a value that keeps the current look of existing projects.
- Every text and graphic token pair must meet WCAG 2.2 AA contrast (4.5:1 for text, 3:1 for graphics) in light and dark mode. Never fix a contrast failure by inventing a new color; use a brand token.
- Text and icons on tinted (`-bg`) surfaces use the matching `--color-*-text` token; every `-text` token must reach 4.5:1 on its `-bg` surface.

## Icons

Components take an `icon` prop, powered by [@nuxt/icon](https://nuxt.com/modules/icon) and Iconify. Use [Material Symbols](https://icones.js.org/collection/material-symbols): `material-symbols:<name>-outline-rounded` first, `-rounded` when the design wants a filled icon, the plain name when neither variant exists. Icons are decorative (hidden from screen readers) unless the component has no text label, so give an icon-only control an `aria-label`. An icon a component shows on first paint goes into `bundledIcons` in [app/utils/icons.ts](app/utils/icons.ts), which the layer's `nuxt.config.ts` puts in the client bundle of every project, so the page does not shift when it loads. A listed icon whose collection a project does not install fails that project's production build, so it comes from Material Symbols or `svg-spinners`, which every project installs.

## MCP

The plugin's `nuxt` MCP server is the Nuxt team's documentation (`https://nuxt.com/mcp`); the playground has no MCP endpoint of its own.
