# Upgrading Cardan UI

This guide is for developers of projects that extend the layer. Each section says what a project must do or check for a release: new tokens for its `main.css`, renamed props or classes, modules or CSP hosts. The components read their design tokens from the project's own `main.css`, a copy of the template in [`app/assets/main.css`](app/assets/main.css), so a token a release adds has to be pasted there.

A release that needs nothing from projects has a one-line section that says so; what it changed is in the playground's changelog ([`.playground/pages/changelog.vue`](.playground/pages/changelog.vue)). The newest minor is at the top. Within a minor, its own notes come first, by topic, and its patch releases follow, newest first. The projects are kept up to date, so the file only holds the five most recent releases that ask something of them, with the one-line sections in between: each release that asks something removes the notes older than that. Older notes are in the history of this file (`git log -p MIGRATION.md`).

## Upgrading to 2.6

Everything in 2.6 is additive, except the identity load of the auth layer (Cardan Auth UI 2.0.0): an app that extends the auth layer adopts it in the same release, in the order below. cardan-support-nuxt and cardan-cms-nuxt extend only the base layer, so neither has to change its app for 2.6, but both notice the config the layer now sets itself: cms no longer lets the browser fetch an icon from Iconify's API and loads its video thumbnails through `/_ipx` in development too, and support, which already carries the layer's Dutch, gets its locales in the order `nl`, `en` (nothing shows it there) and can leave the Dutch out with `i18n.bundle.onlyLocales: 'en'`.

**Every project matches the layer's `@playwright/test`**, 1.65.1 since 2.6.0, in the same change that takes 2.6: a project's specs pass their `Page` and `Locator` to the layer's `test/browser/helpers.ts`, which types them from the layer's own copy, so `pnpm run typecheck` fails in a project on another version (TS2345, in CI too, where the layer's `main` is checked out beside the project). Each project's branch that waits for 2.6 already has it, with the other updates of 24 November 2026 (vue 3.5.46), so all four merge right after the layer.

New: **the auth layer owns the Sanctum setup** that cardan-academy-nuxt and cardan-auditor-nuxt each wrote themselves: the module and its defaults, the identity load at start-up, `Accept-Language` on the API's requests, the language from the address and the profile, the color mode from the profile, the list of sign-in pages and the API's preconnect link. `auth/README.md` describes each. The auth layer is 2.0.0 and its peer `nuxt-auth-sanctum` is `^3.1.5`.

- **The identity load is the one part that is not additive.** The layer's plugin `cardan-auth:identity` asks for the user once in the browser and provides `$identityReady`. An app's own copy runs as well, since Nuxt removes a double plugin by file and not by name, and its second `provide` of `$identityReady` throws at start-up. Remove the app's own identity plugin (the Academy's `app/plugins/identity.client.ts`; the Auditor's `app/plugins/custom-auth.ts`, with its `init()` and `refreshIdentity()` retry and the tests in its `startup.test.ts` that pin them) and its `app/middleware/00.identity.global.ts`. An app's file with that name replaces the layer's, but runs at the app's place, after all of the layer's middleware, so the layer's language resolver and `mfa-setup` would decide before the user is known. Code that awaits `useNuxtApp().$identityReady` keeps working: the promise is the contract, not the plugin's name.
- **The layer registers `nuxt-auth-sanctum` and sets the defaults both apps repeated**: the endpoints `csrf` (`/sanctum/csrf-cookie`), `login` (`/api/login`) and `logout` (`/api/logout`), `client.initialRequest: false`, `redirect.onAuthOnly` and `redirect.onLogout` (`/login`), `redirect.keepRequestedRoute: true`, and `globalMiddleware` with `enabled: true` and `allow404WithoutAuth: false`. Remove these from the app's `sanctum` block, and remove the `runtimeConfig.public.sanctum` block (`baseUrl`, `origin`): the module fills it from the `sanctum` options. The module can go from the app's `modules` (listed twice, Nuxt installs it once), but stays in its `package.json`: a `github:` layer has no `node_modules`.
- **The app keeps what is its own**: `baseUrl`, `origin`, `endpoints.user`, and `redirect.onLogin` and `redirect.onGuestOnly` when the module's `/` is not its home (the Academy's `/dashboard`), plus any default that differs: the Auditor keeps `globalMiddleware: { allow404WithoutAuth: true }`.
- **`sanctum:auth` and `sanctum:guest` do not exist with the global middleware on.** A page for visitors only uses `definePageMeta({ sanctum: { guestOnly: true } })`. Neither app uses the two names.
- **Remove the app's `Accept-Language` plugin** (the Academy's `app/plugins/accept-language.ts`): the layer sends the interface language with every Sanctum request.
- **Remove the app's profile-language code**: the Academy's watcher on `preferred_locale` in `app/layouts/default.vue` and the address half of its `public-locale` middleware, the Auditor's `app/plugins/user-locale.ts`. Name the profile's fields in `app.config.ts` instead, in order: `cardanAuth: { localeFields: ['preferred_locale'] }` in the Academy, `['language', 'team.language']` in the Auditor. The layer adds no field of its own.
- **Set `locale` in the route meta of every route with a language in its address**, the default language's included: the Academy sets `nl` on the Dutch catalog pages in `pages:extend` and `en` on the English copies it makes there, or a visitor going from `/en/catalog` to `/catalog` keeps English.
- **Set `waitForIdentity: false` in the route meta of a cached public page**, in `pages:extend`, so a navigation there does not wait for the user: the Academy's catalog, `/catalog` and below, on the Dutch originals, from which the copies take it. It replaces the path check `isPublicPagePath` in the Academy's identity middleware. Child routes inherit it. A page excluded from the Sanctum middleware that still needs the user first, such as the checkout or the Auditor's report, does not set it.
- **Remove the `setLocale()` after a profile save** (the Auditor's `app/pages/profile.vue` and `app/pages/user/index.vue`): the layer applies the saved language. A page that shows a text right after the save, such as a toast, awaits `useProfileLocale().apply()` after `refreshIdentity()` first, or the text is in the old language.
- **The Academy keeps the language a visitor had last** (`cardan-academy-locale` in local storage) in its own middleware, which runs after the layer's. The layer has no such source.
- **The theme from the profile is off unless named**: the Academy sets `cardanAuth: { themeField: 'settings.theme' }` and removes its theme watcher in `app/layouts/default.vue`; the Auditor leaves it off and keeps the theme in the browser.
- **Replace the app's own list of sign-in paths** (the Academy's in `app/layouts/default.vue`, the Auditor's in `app/components/TheHeader.vue`) with `isAuthPage(path)`, which knows the layer's five pages, `/mfa-setup` included. An app adds its own in `cardanAuth: { authPages: ['/invitations/'] }`: an exact path, or a prefix that ends in `/`.
- **Remove the app's preconnect link to the API** from `app.head`: the layer adds it from `NUXT_PUBLIC_SANCTUM_BASE_URL` at build time.
- **Open the sign-out dialog from a menu with `useLogoutDialog().open()`**, after the menu's `hideMenu()`, and remove the `setTimeout(() => logoutDialogRef.value?.openDialog())` around it (the Academy's `TheUserMenu.vue`, the Auditor's `AppHeaderMenu.vue`): `open()` waits that one task itself.
- **The identity request gives up after 10 seconds.** A signed-in user on an API that does not answer in time is then a guest, and the Sanctum middleware sends them to `/login`. The Academy already works this way; the Auditor waited without a limit and retried.
- **The release order is a step of its own.** Both apps extend `github:cardan-a11y/cardan-ui` unpinned, so once 2.6.0 is on `main`, every Academy build without its adoption fails at start-up, and an Auditor build without it starts but asks for the user twice and waits in two places. So: Cardan UI 2.6.0 to `main` first, then both adoptions at once (each app's `chore/cardan-ui-2.6.0` into `develop`, then its release into `main`), with no other build of either app in between, on `main` or `develop`: no hotfix, no other merge. `pnpm test:projects --branch chore/cardan-ui-2.6.0` passes before the release.

New: **the layer sets the config its own components need**, which each project copied from another until now. The README's section "What the layer configures" describes every key. Config merges, so a project that keeps its copy still works; the copies can go once the project is on 2.6.

- **Remove `fonts.families` with Hanken Grotesk** (the Academy and the Auditor): the layer loads it with the weights `400 800`, in normal and italic, for `latin` and `latin-ext`. A project that keeps its entry has two after the merge; `@nuxt/fonts` makes them one, the project's options first. cardan-cms-nuxt's own Montserrat entry is not affected. A project that set no entry (cardan-support-nuxt) gets the range `400 800` where it was `400 700`, without a change of its own: the same two font files, since Hanken Grotesk is a variable font. `@nuxt/fonts` can also go from the project's `modules`, as can `devtools: { enabled: false }`: the layer registers and sets both.
- **Add `--font-weight-extrabold: 800`** to the font weights in the project's `main.css`, after `--font-weight-bold`. No layer component reads it; it is there for a project's own headings. The Academy and the Auditor already have it.
- **Remove from `vite.optimizeDeps.include` the packages of the layer's components**: markdown-it, `@mdit/plugin-attrs`, `@mdit/plugin-mark`, `highlight.js/lib/core` and the six `highlight.js/lib/languages/*`, `@vuepic/vue-datepicker`, `date-fns`, `date-fns/locale`, `@vueform/multiselect`, `compressorjs` and `md-editor-v3`. The layer's module adds each one the project installs itself, and none it does not, so Vite does not warn about a package it cannot find. Keep the project's own packages in the list (the Auditor's `diff` and `vuedraggable`, `@vueuse/integrations/useChangeCase`). The Academy now also gets `compressorjs`, which it installs without listing it, and the Auditor the bare `date-fns`, which DatePicker imports.
- **Remove `i.ytimg.com` and `i.vimeocdn.com` from `image.domains`**: the layer lists them, at the top level. A project that keeps them has them twice, and `@nuxt/image` removes the duplicates. In the Auditor, cms and the playground, which listed them under `$production` only, a thumbnail in development now goes through `/_ipx` as in production, instead of straight from YouTube or Vimeo. cardan-support-nuxt, which has no `@nuxt/image`, needs no change: the layer writes the key so that its typecheck passes.
- **Remove `icon.clientBundle.scan: true` and `sizeLimitKb: 256`**, which every project set: the layer sets both. Keep the project's own `clientBundle.icons`, which is added to the layer's.
- **`icon.fallbackToApi` is `'server-only'`** in the layer, where it was `true` by default: with the `'server'` provider the browser no longer asks Iconify's API for an icon outside the bundle, and the server still does for a collection the project does not install. This changes cms, the Academy and the playground without a change of theirs; the Auditor already set it and can remove its copy. The layer sets no `provider`, since `@nuxt/icon` chooses it per project: the Auditor, an SPA whose default is `'iconify'`, keeps its `provider: 'server'`, and the Academy's `provider: 'server'` can go: with `ssr` on globally (its `ssr: false` is per route) it is the default. The Auditor can also remove `@iconify-json/vscode-icons`: FileInput's icons are Material Symbols since 2.5.3, and nothing in its `app/` uses the collection.
- **Keep `i18n.locales`** in a project with its own locale files: `@nuxtjs/i18n` loads a layer's locale files only from that layer's own list, so a project without its list loses its `nl.json` and `en.json`. The layer's and the auth layer's lists are now in the order `nl`, `en`, which is the order of LanguageSwitcher and LanguageSelect where the project's own list does not set one. The Academy and cms already list `nl`, `en`; the Auditor changes its list to `nl`, `en` for the same order. cardan-support-nuxt has no list and renders no LanguageSwitcher, so it shows nothing of the order. It sets `i18n.bundle.onlyLocales: 'en'` with its adoption of 2.6, which keeps the layer's Dutch out of its build.

New: **a shared test harness** in the layer's `test/` folder: the vitest config, the browser suite's server and Playwright config, the tripwire runner, the API fakes for vitest and Playwright, the asserting axe helper `expectNoViolations()` and a reusable CI workflow. Existing projects need to do nothing: their own files keep working, also `expect(await checkA11y()).toHaveNoViolations()` with their own `vitest-axe` shim. Each project moves over in its own issue.

Fixed: **DatePicker's calendar with the keyboard.** A project that uses DatePicker raises `@vuepic/vue-datepicker` to `^14.1.0`, as cardan-auditor-nuxt does: 14.1 no longer closes the calendar on Tab from an empty field (Vuepic/vue-datepicker#1283, Cardan Auditor finding CAN-11.F47). The layer's wrapper now puts focus back on the field after Escape or Shift+Tab in the calendar, where the library left it on the page; after a click outside, focus stays where the click put it.

Deprecated: **UserMenu's own sign-out dialog**, its `logout` prop and its `openLogoutDialog()` and `closeLogoutDialog()`. They work as before in 2.6 and are removed in the next major. Use the auth layer's `<LogoutDialog />`, mounted once in the layout, and in the menu item's handler call `hideMenu()`, then `useLogoutDialog().open()`. Neither app uses them.

New: **EmptyMessage**, the text of an empty list or search (`/empty-message` in the playground).

- **It replaces a project's own `<p class="no-results">`**: `<EmptyMessage text="…" />`, or the text in its default slot, with the `v-if` or `v-else` on the component; a button such as "Reset filters" goes in its `actions` slot. Remove the project's `.no-results` styles afterwards.
- **It sets no margin of its own.** Set the spacing the paragraph had where the component is used, with `margin` on a class of the project's own on the component. The layer's reset has no specificity (`:where()`), so the project's rule wins in any stylesheet order, and so does a project's own paragraph rule that reaches it (`.card p`). A rule on `.empty-message` in `main.css` sets it once for every EmptyMessage without actions; one with actions is a wrapper around that paragraph and takes a class.
- **A paragraph that must stay the project's own**, such as a live region that switches between hidden and shown, takes the class `empty-message` for the same look, in a component that also renders an EmptyMessage (its styles load with the component).
- **Its look comes from three optional variables** in `main.css`: `--empty-message-color` (`var(--color-grey-text)`), `--empty-message-font-size` (`1em`, the surrounding size) and `--empty-message-font-style` (`normal`). The Auditor keeps its small italic with `--empty-message-font-size: var(--font-size-sm)` and `--empty-message-font-style: italic`. On a tinted (`-bg`) surface, set `--empty-message-color` to the matching `--color-*-text` there.

New: **`useNumber()`**, numbers, percentages and prices in the app's language (`/numbers` in the playground).

- **It returns `formatNumber(value, { decimals? })`, `formatPercent(fraction, { decimals? })` and `formatCurrency(amount, { currency, cents, decimals })`** in the i18n locale; the pure versions, with a `locale` argument, are in `app/utils/number.ts`. A price is in euros by default, from cents with `cents: true`, and without decimals when the amount is whole (`decimals: 0` never shows them).
- **It replaces a project's own price formatter** (`formatPrice()`) **and every `toLocaleString()` without a locale**, which follows the browser's language instead of the app's.
- **`formatPercent` takes a fraction**, as `Intl.NumberFormat` does: divide a whole percentage by 100 and per mille by 1000 at the call.
- PricingCard, Chip and `formatFileSize()` use them; what they show is unchanged.

New: **`useDialog(key)`**, a dialog opened from another component (`/dialog` in the playground).

- **It holds a dialog's ref under a key**: `const { dialogRef, close } = useDialog('audit')` with `<Dialog ref="dialogRef">` in the dialog's own component, `useDialog('audit').open()` anywhere else. `close()` resolves once the dialog has closed and `isOpen` follows it. It works for MobileMenu too, `useDialog<MobileMenuComponent>('menu')`, whose `close()` resolves at once. Mount one dialog per key: development warns about a second one, and about `open()` on a key without a mounted dialog.
- **A project's own `useDialog` composable shadows the layer's** (the Auditor's `app/composables/useDialog.ts`), since a project's composable wins over one of the same name. Keep it until every caller has moved to the layer's, then delete it in the same commit. The auth layer is not affected: it calls the layer's under another name, `useLayerDialog`.
- **Typed keys are optional**: any string is a key until a project lists its own in the global `DialogKeys` interface (`declare global { interface DialogKeys { audit: true } }`), which makes a typo a type error. The auth layer's keys stay valid.
- **The auth layer's `useLogoutDialog()`, `useMfaDialog()` and `usePasswordConfirmation()` use it**, under the keys `auth:logout`, `auth:mfa`, `auth:mfa-recovery-codes` and `auth:password-confirmation`. They return the same names, so `logoutDialogRef.value?.openDialog()` keeps working; `closeMfaDialog()` and `closeMfaRecoveryCodesDialog()` now return a promise that resolves once the dialog has closed.

New: **ConfirmDialog**, **ConfirmDialogHost** and **`useConfirm()`**, one "are you sure?" dialog that only runs the action of the caller that opened it (`/confirm-dialog` in the playground).

- **To use `useConfirm()`, mount `<ConfirmDialogHost />` once in the layout**, next to ToastManager and LogoutDialog. Without it `confirm()` resolves `false` and runs nothing.
- **The action travels with the request**: `confirm({ label, description, onConfirm: () => deleteAudit(audit) })`, with the item in the closure. It resolves `true` once the action succeeded and the dialog has closed, `false` after a cancel; when the action throws, the dialog stays open and shows the error. After a confirmed delete, move focus yourself when the button that opened the dialog went with the item.
- **`challenge: true` asks for a random digit first**, the Auditor's `method="input"`; `autofocus` starts focus in that field. The keys `general.confirm-number` and `general.confirm-number-description` are in the layer: a project drops its own copies.
- **A dialog with markup in its text is a declarative `<ConfirmDialog>`**, with the text in its default slot, as the Academy's cart names the course in a `<strong lang>`. It emits `confirm` and `cancel` and keeps its state to itself.
- **LogoutDialog (the auth layer) is a ConfirmDialog now**: `role="alertdialog"`, 420px wide, focus starts on Cancel. `useLogoutDialog()` is unchanged. A project's test that finds it by `role="dialog"` looks for `alertdialog`.
- **Dialog has a `focus-cancel` prop**, which starts focus on its Cancel button.

New: **ComboBox**, our own searchable single select (`/combobox` in the playground). **MultiSelect is deprecated**: it works as before in 2.6 and is removed in the next minor, with `@vueform/multiselect`.

- **A single select moves over by changing the tag.** `v-model`, `options`, `label`, `value-key`, `label-key`, `size`, `name`, `required`, `disabled`, `placeholder`, `loading` and `no-options-text` keep their names. Remove `mode`, `searchable`, `autocomplete="off"`, `resolve-on-load`, `clear-on-search`, `native-support`, `object` and the `@open` workaround: ComboBox is always single and searchable, and loads a function's options when the field is first touched, or at once for a value without its option. An array that the page still fetches goes with `loading`, so a value shows no "Unknown option" meanwhile.
- **An empty string is a value**, where MultiSelect counted it as empty: a field that starts at `''` passes `required`, shows "Unknown option" and submits `name=`, unless an option has the value `''`. Start it at `undefined` or `null`. **Disabled options** came in 2.6.2 (`disabled-key`, below).
- **`can-clear` and `can-deselect` are one prop, `can-clear`**, on by default. Picking the selected option again only closes the list; clearing is the clear button, or emptying the field and leaving it. A clear emits `null`.
- **`v-model.number` goes**: the value is the option's value as it is.
- **`name` puts the option's value in the form's `FormData`**, through a hidden input, where MultiSelect needed `native-support`. A disabled ComboBox submits nothing, as a native control: a form that sends its `FormData` and needs the value of a disabled field sets it itself.
- **`object` becomes `v-model:selected`**, which holds the selected option next to the value in `v-model`. With it a field shows its label without loading its list.
- **Typed text is never a value, and typing picks nothing.** When focus leaves, or before its Form checks a submit, the field shows the selected option's label again, and a field the user emptied clears the value. Enter and Tab pick only an option the arrow keys highlighted.
- **A project that styled a set filter** through `.multiselect-single-label` or `.multiselect-option.is-selected` uses the class `has-value` on ComboBox's wrapper.
- **A project's test** finds the text field by `role="combobox"` and its label; the name no longer holds the selection, which is the field's value.
- **Selecting several, tags and the create option** came in 2.6.2 (below).
- **A list too long to load whole takes `server-search`**: the function is then `options(query, { signal, page })`, asked after a pause in typing, and may answer one page as `{ options, more }`. Such a field needs `v-model:selected` to show the label of its value.
- **Browsers**: nothing new. ComboBox needs what Tooltip, Popover and UserMenu already need; the README now lists the supported browsers with their versions.

### 2.6.3

Changed: **MarkdownPreview's safe mode shows an image only from a first-party host**: the page's own origin, or a host the project lists in its `app.config.ts`. Any other image, which told its host who read the text and when, is now a link to it with its alt text; a `data:` image, which asks no host, still shows. `trusted` is unchanged, and so is MarkdownEditor apart from its preview, which follows the same list.

- **List the hosts the project's markdown images come from**, first-party only: `defineAppConfig({ cardan: { markdownImageHosts: ['cdn.example.com'] } })`, a host (for `https`) or an origin. cardan-academy-nuxt lists the bucket the API's `AWS_PUBLIC_ASSETS_URL` points at (`cardan-lms-prod.fsn1.your-objectstorage.com`, already in its `image.domains`) and its API's origin (from `NUXT_PUBLIC_SANCTUM_BASE_URL`, which is `http:` locally: list the origin, not the bare host); every image in its production content is in that bucket, checked on 27 November 2026, so none becomes a link. cardan-auditor-nuxt lists nothing: its editor has no image button and its texts link to no upload host, but a hand-typed image from another host in a finding or comment is now a link (its stored texts were not checked). cardan-cms-nuxt and cardan-support-nuxt do not use MarkdownPreview and need to do nothing.
- **A link to another origin gets `rel="noopener"`**, and a protocol-relative link (`//example.com`) now opens in a new window as one too. Nothing to do.

New: **`useCookiesDialog().pushDataLayer(event)`** sends a project's own event to Google Tag Manager, such as a form submission, and drops it until the visitor has accepted cookies, or when the project has no `gtmId`. CookiesDialog is the one place that registers Tag Manager, behind its consent trigger.

- **Replace a project's own `useScriptGoogleTagManager()` with `pushDataLayer()`.** A second registration, without the consent trigger, loads Tag Manager on the page at once, before any choice: cardan-cms-nuxt's `PageBlockForm.vue` does this today on every page with a form. There `gtm.proxy.dataLayer.push({ event: 'formSubmission', … })` becomes `pushDataLayer({ event: 'formSubmission', … })`, and the call to `useScriptGoogleTagManager()` goes; its vitest mock of that composable can go too. The event of a visitor who did not accept is then dropped instead of sent. cardan-cms-nuxt does this on `chore/cardan-ui-2.6.3`, which merges only after this release is on `main`. The other projects do not use Tag Manager.
- **Accept after a Deny in the same visit now loads Tag Manager**: a Deny before any Accept cancelled the script for the rest of the visit, so the visitor's Accept had no effect until the next page load. Nothing to do.

Fixed: **FileInput's form post carries the compressed image.** Once compressorjs is done, FileInput writes the result to its input as well as to its value, and emits the new `ready` with it; a GIF, a file that is not an image or a failed compression keeps the original and emits `ready` with that. A submit before `ready` posts the original, which passed `maxFileSize`. compressorjs now loads only when an image is chosen; keep it installed.

- **Remove the `formData.set(...)` that put the compressed file in the post by hand**: cardan-academy-nuxt's `UserProfileForm.vue` (`avatar`), cardan-auditor-nuxt's `FileUploadForm.vue`, `FindingForm.vue` and `TeamDialog.vue`. In `TeamDialog.vue` this also fixes `logo_dark`, which went uncompressed.
- **Call `reset()` instead of setting `validity` or `imagePreview` from outside** (cardan-auditor-nuxt's `FileUpload.vue` and `useFileUpload.ts`): it empties the value, the input and the preview. Both refs stay exposed for now.

Fixed: **small defects in the field components**.

- **CheckboxGroup's `v-model` is typed as an array**, `(string | number)[]`, where it also allowed a boolean, and the group treats any other model as empty: `undefined` or `null` made the first tick tick every box. Every project binds an array. Nothing to do.
- **Select shows its placeholder for `undefined` and `null`**, and no "No options" entry next to options in its slot. Nothing to do.
- **RadioGroup counts only an option's value as a choice**, so a required group with `null` or a value no option has shows its error after a failed submit. Nothing to do.
- **A disabled or read-only required field is no longer `aria-invalid`** after a failed submit, nor described by an error that does not show: Checkbox, CheckboxGroup, RadioGroup, DatePicker, ComboBox, SpinButton, FileInput and MarkdownEditor, which no longer holds a submit back while disabled. Nothing to do.

### 2.6.2

New: **ComboBox `multiple`**, which selects several options, and ComboBox's **`create-option`** and **`disabled-key`** (`/combobox` in the playground). With them every MultiSelect field has its ComboBox; MultiSelect is removed in the next minor, so move each field over and then remove `@vueform/multiselect` from the project's `package.json`. cardan-auditor-nuxt, the only project that still uses MultiSelect, does this on `chore/cardan-ui-2.6.2`, which merges only after this release is on `main`.

- **A field with `mode="multiple"` or `mode="tags"` becomes `<ComboBox multiple>`.** Remove `mode`, `:close-on-select="false"` and `show-option-icons`: the popup is a dialog of checkboxes, which stays open while the user ticks. `items-selected-label` has no counterpart: the closed field shows the label of one option, or "3 selected". The other props are those of a single select in 2.6, above.
- **`v-model` is an array of values**, `[]` after a clear; `v-model:selected` holds their options. `name` gives a hidden input per value, and `required` asks for one at least. `multiple` is read once, when the field is created, and types the model: development warns about a mode change after mount and a value of the other mode's type.
- **Not with `server-search`**: a list too long to load whole needs a page of its own.
- **The create option is `create-option`**, with `create-text` for its text, and emits `create` with the typed text, in both modes. The parent creates the record, adds it to `options` and sets the value (in `multiple`, adds it to the array); `v-model:selected` shows the new option's label before the list reloads, and a failed create shows in `custom-error`. Not with `server-search`. MultiSelect's `@create` handler that returned the option goes.
- **`disabled-key`** (`disabled` by default) marks an option that a search and the arrow keys reach, but nothing picks: `aria-disabled` in the list, an `aria-disabled` Checkbox with `multiple`, which a clear keeps ticked. An option a project left out of `options` for 2.6 can come back.
